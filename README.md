# MAHDI — Mitigation Algorithm for Halo and Diffuse Illumination

**MAHDI** is a Python-based pipeline designed to model and subtract the extended scattered-light halos produced by bright foreground stars in deep astronomical imaging. It works with extended point spread function (PSF) models, such as those generated by [LISAN](https://github.com/CarlosMDLR/LISAN), to select suitable stars, determine star-specific normalization regions, scale the PSF, and remove stellar contamination from science images.

The main objective is to improve the recovery of low-surface-brightness structures such as stellar halos, tidal features, faint galaxy outskirts, and intracluster light.

---

## Purpose and capabilities

MAHDI can:

- Detect and segment sources in the input images with GNU Astronomy Utilities (Gnuastro).
- Select foreground stars within a configurable Gaia G-magnitude range.
- Crossmatch the selected stars with Gaia DR3 and store their Gaia `source_id` values.
- Protect selected Gaia sources from subtraction through a user-provided exclusion list.
- Create rectangular stellar cutouts with independently configurable height and width.
- Measure radial stellar profiles and estimate characteristic radii.
- Determine star-specific PSF-normalization annuli.
- Scale and subtract an extended PSF model for every selected star.
- Process stars from brightest to faintest to reduce contamination between overlapping stellar halos.
- Optionally build a combined scattered-light model for the complete image.
- Optionally save the individual scattered-light model generated for each star.
- Save intermediate catalogs, stellar cutouts, radial profiles, normalization factors, masks, model images, and final star-subtracted images.

MAHDI is intended for deep-imaging studies reaching surface-brightness levels of approximately 30 mag arcsec\(^{-2}\), although the effective depth depends on the input data, reduction strategy, PSF characterization, and background treatment.

---

## Scientific motivation

Bright stars generate extended scattered-light halos that can reach hundreds or thousands of pixels from their centers. In deep observations, these halos may overlap galaxies or mimic diffuse astrophysical structures. A reliable correction requires more than masking the central stellar pixels: the extended PSF must be scaled to each star and subtracted over the full region affected by scattered light.

MAHDI follows this general strategy:

1. Select candidate stars using `astscript-psf-select-stars`.
2. Crossmatch their coordinates and Gaia G magnitudes with Gaia DR3.
3. Add the Gaia DR3 `source_id` and the angular crossmatch separation to the stellar catalog.
4. Remove protected stars whose Gaia IDs appear in a user-provided exclusion file.
5. Create cutouts centered on the remaining stars.
6. Measure radial profiles and derive suitable PSF-normalization regions.
7. Scale the corresponding extended PSF model to each star.
8. Subtract the stars iteratively from brightest to faintest.
9. Optionally accumulate the individual stellar models into a full scattered-light map.

The Gaia crossmatch is performed before stellar cutouts, radial profiles, or PSF subtraction are generated. Consequently, a protected star is excluded from the complete subtraction workflow rather than being removed only from the final catalog.

## Gaia DR3 crossmatch and protected-star list

`astscript-psf-select-stars` provides the coordinates and Gaia G magnitudes of the selected stars, but it does not necessarily preserve their Gaia source identifiers. MAHDI therefore performs an additional positional and photometric crossmatch against `gaiadr3.gaia_source`.

For each selected source, MAHDI:

- uploads a compact table containing the selected coordinates and magnitudes to the Gaia TAP service;
- retrieves all Gaia DR3 candidates within `--gaia-match-radius-arcsec`;
- rejects candidates whose G-magnitude difference exceeds `--gaia-match-max-mag-diff`;
- chooses the best remaining match, prioritizing angular separation and then magnitude agreement;
- stores the matched `source_id` and `gaia_match_separation_arcsec` in the FITS catalog.

Sources without an acceptable Gaia match are retained with:

```text
source_id = -1
gaia_match_separation_arcsec = NaN
```

These unmatched stars can still be processed and subtracted, but they cannot be identified through a Gaia-ID exclusion list.

### Gaia query cache

Gaia query results are cached locally, by default under:

```text
./Process_data/Gaia_catalogs/
```

A cached result is reused only when both of the following match the current run:

- the selected-star catalog, identified from its coordinates and magnitudes;
- the configured Gaia crossmatch radius.

Changing the selected catalog or `--gaia-match-radius-arcsec` triggers a new query. Changing only the maximum magnitude difference reuses the same candidate cache and reapplies the local matching criterion.

### Protecting stars from subtraction

Use `--gaia-ids-not-subtract` to provide a text file containing Gaia DR3 IDs that must not be subtracted.

Example:

```text
# Bright star intentionally preserved
1234567890123456789

# Several IDs may appear on one line
2345678901234567890, 3456789012345678901
4567890123456789012; 5678901234567890123
```

The file accepts:

- one or several IDs per line;
- whitespace, commas, or semicolons as separators;
- comments beginning with `#`;
- blank lines.

Invalid non-integer values cause the pipeline to stop with an explicit error. Gaia IDs must be written as integers rather than scientific notation.

- `mahdi.py`: command-line entry point and pipeline orchestration.

- `Gaia_catalogs/`: cached Gaia DR3 crossmatch candidates.
- `Mask_noisechisel/`: full-image NoiseChisel products.
- `Mask_segment/`: segmentation maps and temporary subtraction products.

- `Norm_radii/`: stellar cutouts, radial profiles, and rejected close sources.
- `Normalization_factors/`: PSF scale factors and normalization radii.
- `Subtrac_copy_{filter}/`: working copies and final star-subtracted science images.
- `Full_scatter_maps_{filter}/`: combined scattered-light models when `--model-scatter` is enabled.
- `Scatter_field_{filter}/`: individual stellar scattered-light models when they are explicitly retained.

## Installation and dependencies

A dedicated Python virtual environment is recommended.

```bash
python3 -m venv mahdi_env
source mahdi_env/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The Python dependencies include packages such as:

- NumPy
- pandas
- SciPy
- Astropy
- astroquery
- scikit-learn
- Matplotlib
- tqdm

The Gaia DR3 crossmatch requires `astroquery`. It can be installed independently with:

```bash
python -m pip install astroquery
```

MAHDI also requires [GNU Astronomy Utilities](https://www.gnu.org/software/gnuastro/). The pipeline calls several Gnuastro programs directly, including:

```text
astnoisechisel
astsegment
astcrop
asttable
astarithmetic
astscript-psf-select-stars
astscript-radial-profile
astscript-psf-scale-factor
astscript-psf-subtract
```

These commands must be available in the shell environment used to run MAHDI.

A working internet connection is required when a valid Gaia cache is not already available.

## Input naming conventions

### Science images

The input directory provided through `--dir` should contain FITS images named approximately as:

```text
{galaxy}_{filter}.fits
```

Examples:

```text
IC1101_g.fits
IC1101_r.fits
NGC2543_g.fits
NGC2543_r.fits
```

MAHDI identifies the galaxy name from the part of the filename preceding the first underscore.

### PSF models

The directory provided through `--dir-psf` must contain the two products required for each galaxy and filter:

```text
psf_{galaxy}_{filter}.fits
psf_profile_{galaxy}_{filter}.fits
```

For example:

```text
psf_IC1101_g.fits
psf_profile_IC1101_g.fits
psf_IC1101_r.fits
psf_profile_IC1101_r.fits
```

The first file is used for PSF scaling and subtraction. The radial PSF profile is used to relate stellar magnitude, surface brightness, and normalization radius.

## Command-line usage

Run:

```bash
python3 mahdi.py --help
```

The available arguments are:

```text
usage: mahdi.py [-h] --dir DIR --dir-psf DIR_PSF [--hdu HDU]
                [--psf-hdu PSF_HDU] --filters FILTERS
                --mag-inf-sub MAG_INF_SUB --mag-sup-sub MAG_SUP_SUB
                --min-dist-sub MIN_DIST_SUB [--model-scatter]
                [--save-individual-scatter-maps] [--px-scale PX_SCALE]
                [--crop-size-pix HEIGHT WIDTH] [--zp ZP]
                [--gaia-ids-not-subtract GAIA_IDS_NOT_SUBTRACT]
                [--gaia-match-radius-arcsec GAIA_MATCH_RADIUS_ARCSEC]
                [--gaia-match-max-mag-diff GAIA_MATCH_MAX_MAG_DIFF]
                [--gaia-cache-dir GAIA_CACHE_DIR]
                [--noisechisel-params-full-image NOISECHISEL_PARAMS_FULL_IMAGE]
                [--segment-params-full-image SEGMENT_PARAMS_FULL_IMAGE]
                [--noisechisel-params NOISECHISEL_PARAMS]
                [--segment-params SEGMENT_PARAMS]
```

### Required arguments

| Argument | Description |
|---|---|
| `--dir` | Directory containing the input galaxy FITS images. |
| `--dir-psf` | Directory containing the PSF images and PSF radial profiles. |
| `--filters` | Comma-separated list of filters, for example `g,r`. |
| `--mag-inf-sub` | Lower Gaia G-magnitude limit used by the stellar-selection step. |
| `--mag-sup-sub` | Upper Gaia G-magnitude limit used by the stellar-selection step. |
| `--min-dist-sub` | Minimum angular distance between selected stars, in degrees. |

### Image and PSF arguments

| Argument | Default | Description |
|---|---:|---|
| `--hdu` | `0` | HDU containing the science image. |
| `--psf-hdu` | `0` | HDU containing the PSF image. |
| `--px-scale` | `0.33` | Pixel scale in arcsec pixel\(^{-1}\). |
| `--crop-size-pix HEIGHT WIDTH` | `500 500` | Height and width of each stellar cutout in pixels. |
| `--zp` | `22.5` | Photometric zero point used for surface-brightness conversion. |

The crop dimensions are supplied as two separate integers. For example:

```bash
--crop-size-pix 600 400
```

creates cutouts 600 pixels high and 400 pixels wide.

### Scattered-light outputs

| Argument | Default | Description |
|---|---:|---|
| `--model-scatter` | disabled | Construct and save the combined scattered-light field. |
| `--save-individual-scatter-maps` | disabled | Preserve the individual model image generated for every star. This option is relevant when scattered-light modeling is enabled. |

### Gaia crossmatch and exclusion arguments

| Argument | Default | Description |
|---|---:|---|
| `--gaia-ids-not-subtract` | `None` | TXT file containing Gaia DR3 `source_id` values that must be excluded from subtraction. |
| `--gaia-match-radius-arcsec` | `1.0` | Maximum positional separation allowed during the Gaia crossmatch, in arcseconds. Must be greater than zero. |
| `--gaia-match-max-mag-diff` | `0.1` | Maximum absolute Gaia G-magnitude difference allowed for a match. Must be non-negative. |
| `--gaia-cache-dir` | `./Process_data/Gaia_catalogs` | Directory used to store and reuse Gaia DR3 candidate tables. |

### Masking arguments

| Argument | Default | Description |
|---|---:|---|
| `--noisechisel-params-full-image` | internal defaults | Additional `astnoisechisel` parameters for the complete science images. |
| `--segment-params-full-image` | internal defaults | Additional `astsegment` parameters for the complete science images. |
| `--noisechisel-params` | internal defaults | Additional `astnoisechisel` parameters for the stellar cutouts. |
| `--segment-params` | internal defaults | Additional `astsegment` parameters for the stellar cutouts. |

Parameters containing spaces must be enclosed in quotes, for example:

```bash
--noisechisel-params-full-image="--tilesize=30,30 --snminarea=3"
```

## Example execution

Suppose that:

- science images are stored in `./Process_data/Beard_cut/`;
- PSF models and profiles are stored in `./PSF_files/PSFs_complete/`;
- the science and PSF data are in HDU 1;
- the filters are `g` and `r`;
- protected Gaia IDs are listed in `./gaia_ids_not_subtract.txt`.

The complete pipeline can be executed as:

```bash
python3 mahdi.py \
    --dir ./Process_data/Beard_cut \
    --dir-psf ./PSF_files/PSFs_complete \
    --hdu 1 \
    --psf-hdu 1 \
    --filters g,r \
    --mag-inf-sub 12.5 \
    --mag-sup-sub 12.9 \
    --min-dist-sub 0.003 \
    --model-scatter \
    --save-individual-scatter-maps \
    --px-scale 0.33 \
    --crop-size-pix 600 400 \
    --zp 22.5 \
    --gaia-ids-not-subtract ./gaia_ids_not_subtract.txt \
    --gaia-match-radius-arcsec 1.0 \
    --gaia-match-max-mag-diff 0.1 \
    --gaia-cache-dir ./Process_data/Gaia_catalogs \
    --noisechisel-params-full-image="--tilesize=30,30" \
    --noisechisel-params="--tilesize=30,30"
```

To perform the Gaia crossmatch without protecting any source, omit:

```bash
--gaia-ids-not-subtract ./gaia_ids_not_subtract.txt
```

The Gaia crossmatch itself remains active because the resulting IDs and match separations are stored in the generated catalogs.

## Pipeline workflow

### 1. Full-image mask generation

Every input FITS image is processed with NoiseChisel and Segment. The resulting products are stored under:

```text
Process_data/Mask_data/Mask_noisechisel/
Process_data/Mask_data/Mask_segment/
```

These segmentation products are later used during PSF normalization and subtraction.

### 2. Initial stellar selection

`astscript-psf-select-stars` selects stars using:

- the configured G-magnitude interval;
- the minimum angular separation;
- the WCS and image footprint of the input FITS file.

The initial catalog is written as:

```text
Process_data/Subtract_stars/Quit_stars_{filter}/
└── Stars_{galaxy}_{filter}/
    └── {galaxy}_{filter}_quit.fits
```

### 3. Gaia DR3 crossmatch

The initial catalog is crossmatched with Gaia DR3. MAHDI adds:

```text
source_id
gaia_match_separation_arcsec
```

The crossmatch summary reports:

```text
selected stars
matched stars
unmatched stars
protected stars removed
stars retained for subtraction
```

### 4. Protected-star filtering

When `--gaia-ids-not-subtract` is supplied, all matched sources whose `source_id` appears in the TXT file are removed from `{galaxy}_{filter}_quit.fits` before further processing.

They therefore do not produce:

- stellar cutouts;
- masks;
- radial profiles;
- normalization regions;
- PSF models;
- subtraction operations.

### 5. Stellar cutouts and radial profiles

For every retained star, MAHDI creates a WCS-centered rectangular cutout using the dimensions supplied through `--crop-size-pix HEIGHT WIDTH`.

NoiseChisel and Segment are run on each cutout. MAHDI then measures a radial profile and estimates the radius where the stellar profile becomes sufficiently flat.

### 6. Normalization-region determination

MAHDI uses the measured stellar profiles, a RANSAC regression, and the supplied PSF radial profile to determine the inner and outer normalization radii for each star.

The PSF profile is integrated and used to construct a lookup table relating:

- Gaia G magnitude;
- surface brightness;
- PSF radius.

The current implementation evaluates normalization radii corresponding to internal surface-brightness levels of 20.5 and 23 mag arcsec\(^{-2}\).

### 7. Cleaning overlapping sources

When selected sources overlap, MAHDI retains the brightest relevant source and moves rejected stellar cutouts into the corresponding `close_sources` directory.

### 8. Revised stellar catalog

The final catalog is written as:

```text
{galaxy}_{filter}_quit_revised.fits
```

It contains:

```text
ra
dec
phot_g_mean_mag
source_id
gaia_match_separation_arcsec
rmin_norm
rmax_norm
image_index
```

The `image_index` column connects every final source to its corresponding cutout and diagnostic products.

### 9. PSF scaling and subtraction

The revised catalog is sorted by `phot_g_mean_mag`, so stars are processed from brightest to faintest. For each source, MAHDI:

1. measures a PSF scale factor inside its normalization annulus;
2. records the scale factor and normalization radii;
3. subtracts the scaled PSF from the working science image;
4. uses the resulting image as the input for the next star.

The final star-subtracted image is stored under:

```text
Process_data/Subtract_stars/Subtrac_copy_{filter}/{galaxy}_{filter}/
```

### 10. Optional scattered-light model

When `--model-scatter` is enabled, MAHDI also:

- creates a model-only image for each star;
- accumulates the individual models into a complete scattered-light field;
- saves the combined field in image units;
- creates a surface-brightness version using `--zp` and `--px-scale`.

The combined products are written under:

```text
Process_data/Subtract_stars/Full_scatter_maps_{filter}/{galaxy}_{filter}/
```

Individual stellar models are retained only when `--save-individual-scatter-maps` is also supplied.

## Current status

MAHDI is under active development. The current version includes:

- command-line configuration through `argparse`;
- full-image masking with NoiseChisel and Segment;
- stellar selection with `astscript-psf-select-stars`;
- automatic Gaia DR3 positional and photometric crossmatching;
- local Gaia query caching;
- optional exclusion of user-selected Gaia IDs;
- configurable rectangular stellar cutouts;
- radial-profile analysis;
- RANSAC-based estimation of the stellar magnitude–radius relation;
- PSF-profile-based normalization annuli;
- iterative PSF subtraction;
- optional full scattered-light-field modeling;
- optional preservation of individual stellar model images;
- diagnostic catalogs, masks, cutouts, profiles, and normalization products.

### Planned improvements

Potential future developments include:

- more advanced treatment of overlapping stellar halos;
- configurable policies for unmatched or ambiguous Gaia sources;
- offline Gaia-catalog input without TAP queries;
- improved failure recovery and execution summaries;
- parallel or accelerated processing for large images;
- tighter integration with LISAN output products;
- expanded automated diagnostics and quality-control plots.

## Troubleshooting

### `astroquery` is not installed

Install it with:

```bash
python -m pip install astroquery
```

### Gaia query fails

Check:

- that the machine has internet access;
- that the Gaia Archive service is available;
- that `astroquery` and its dependencies are installed;
- whether a valid cached table already exists under `--gaia-cache-dir`.

MAHDI stops the affected galaxy when neither a successful query nor a valid cache is available. It does not silently continue without attempting to assign Gaia IDs.

### A protected star is still subtracted

Inspect the initial FITS catalog and verify:

- that the source has a valid `source_id` rather than `-1`;
- that its `gaia_match_separation_arcsec` is reasonable;
- that the ID in the TXT file exactly matches the integer stored in the FITS table;
- that the configured match radius and magnitude tolerance are sufficiently permissive.

### No acceptable Gaia match is found

Consider increasing one or both of:

```bash
--gaia-match-radius-arcsec
--gaia-match-max-mag-diff
```

Large tolerances may increase the risk of incorrect associations, particularly in crowded fields. The stored match separation should therefore be reviewed when changing these parameters.

### Rectangular cutout dimensions appear reversed

The syntax is:

```bash
--crop-size-pix HEIGHT WIDTH
```

For example:

```bash
--crop-size-pix 600 400
```

means 600 pixels in height and 400 pixels in width.
